<task type="auto">
  <name>Task 2: Create strategy dispatcher with RRF fusion and auto-routing</name>
  <files>pageindex/retrieval/strategy.py, pageindex/retrieval/__init__.py</files>
  <action>
Create `pageindex/retrieval/strategy.py` with the following components. Follow existing codebase conventions: stdlib dataclasses, logging module, tenacity retry for LLM calls, litellm.completion() for structured output.

**Imports:**
- `from __future__ import annotations`
- `import json`, `import logging`
- `import litellm` and `from tenacity import retry, stop_after_attempt, wait_random_exponential`
- From the retrieval package: `search_metadata` from `.metadata`, `search_semantic, embed_query` from `.semantic`, `search_description` from `.description`, `load_retrieval_config` from `.config`, `FusedResult, SearchResponse, QueryClassification, assign_confidence` from `.models`, `CLASSIFICATION_SCHEMA, CLASSIFICATION_SYSTEM_PROMPT` from `.prompts`
- From llm config: `from pageindex.llm.config import load_llm_config`

**Module logger:** `logger = logging.getLogger(__name__)`

**Functions to implement:**

1. **`_llm_completion(model, messages)`** -- Internal helper wrapping `litellm.completion()` with `response_format=CLASSIFICATION_SCHEMA`. Decorated with `@retry(wait=wait_random_exponential(min=1, max=30), stop=stop_after_attempt(3))`. Resolves model from parameter or `load_llm_config()["completion_model"]` if None. Returns `response.choices[0].message.content` as string. Same pattern as `_llm_completion` in metadata.py.

2. **`classify_query(query, model=None)`** -- Calls `_llm_completion` with system=CLASSIFICATION_SYSTEM_PROMPT and user=query. Parses JSON response. Maps intent to strategy: `{"structured": "metadata", "conceptual": "semantic", "mixed": "hybrid"}`. Returns `QueryClassification` dataclass. On ANY exception (JSON parse, key error, LLM failure), logs warning and returns fallback: `QueryClassification(intent="mixed", strategy="hybrid", reasoning="Classification failed, defaulting to hybrid", structured_indicators=[])`. This is the anti-pattern avoidance from RESEARCH Pitfall 5.

3. **`reciprocal_rank_fusion(ranked_lists, k=60, weights=None)`** -- Pure function implementing weighted RRF per RESEARCH Pattern 2. Parameters: `ranked_lists: dict[str, list]` (engine_name -> sorted results), `k: int` (RRF constant), `weights: dict[str, float] | None` (per-engine weight, default 1.0 for all). Accumulates `weight / (k + rank)` per doc_id. Builds `FusedResult` for each unique doc_id with fused_score, engine_scores dict, contributing_engines list. Confidence assigned using `assign_confidence(fused_score, "hybrid")` -- add a "hybrid" entry to CONFIDENCE_THRESHOLDS in config.py with thresholds `{"high": 0.03, "medium": 0.015}` (RRF scores are in ~0.01-0.05 range). Metadata for FusedResult: look up from the first engine result that contributed the doc_id. Returns list sorted by fused_score descending.

4. **`_run_metadata_first(query, limit, model)`** -- Per RESEARCH Pattern 4 and CONTEXT decisions. Run `search_metadata(query, limit=limit, model=model)`. If len(results) < `cfg["metadata_fallback_threshold"]` (default 3), supplement with `search_semantic(query, limit=limit)`. Deduplicate by doc_id (metadata results take priority). Truncate to limit. Wrap each result in the list as-is (they are already RetrievalResult subclasses). Return `(results, engine_gaps)` tuple where engine_gaps is empty list (single-engine modes don't report gaps).

5. **`_run_semantic_first(query, limit)`** -- Run `search_semantic(query, limit=limit)`. Return results directly. Simpler than metadata-first: no fallback needed per CONTEXT decisions ("pure conceptual queries route to semantic-first"). Return `(results, [])` tuple.

6. **`_run_hybrid(query, limit, model)`** -- The core hybrid fusion function. Per CONTEXT decisions (locked):
   - Read config: `cfg = load_retrieval_config()`
   - Compute fetch_size: `limit * cfg["internal_fetch_multiplier"]`
   - Compute query embedding ONCE: `query_emb = embed_query(query)` (Pitfall 3 from RESEARCH -- avoid double embedding)
   - Run all three engines with fetch_size:
     - `meta_results = search_metadata(query, limit=fetch_size, model=model)`
     - `sem_results = search_semantic(query, limit=fetch_size, query_embedding=query_emb)`
     - `desc_results = search_description(query, limit=fetch_size, query_embedding=query_emb)`
   - Note: `search_semantic` and `search_description` both accept `query_embedding` parameter. Check their signatures; if they don't accept it yet, pass the query string instead and document a TODO. But per Phase 3 SUMMARY, embed_query is shared -- verify both functions accept `query_embedding` kwarg.
   - Build ranked_lists dict: `{"metadata": meta_results, "semantic": sem_results, "description": desc_results}`
   - Track engine_gaps: any engine with 0 results gets added to gaps list
   - Log engine_gaps if any: `logger.info(f"Engine gaps in hybrid search: {engine_gaps}")`
   - Call `reciprocal_rank_fusion(ranked_lists, k=cfg["rrf_k"], weights=cfg["engine_weights"])`
   - Filter by `global_min_score`: remove FusedResults with fused_score < cfg["global_min_score"]
   - Truncate to limit
   - Return `(fused_results, engine_gaps)` tuple

7. **`search(query, strategy="auto", limit=None, model=None)`** -- The main entry point (per RESEARCH Pattern 1 and CONTEXT decisions):
   - `cfg = load_retrieval_config()`
   - `effective_strategy = strategy if strategy != "auto" else None` (resolved later)
   - `effective_limit = limit if limit is not None else cfg.get("default_top_k", 10)`
   - Validate strategy is one of: "metadata", "semantic", "hybrid", "auto". Raise `ValueError` otherwise.
   - If strategy == "auto": call `classify_query(query, model=model)`, get classification. Set `effective_strategy = classification.strategy`, `reasoning = classification.reasoning`. Log: `logger.info(f"Auto strategy selected: {effective_strategy} (intent: {classification.intent})")`.
   - Else: `effective_strategy = strategy`, `reasoning = f"User-selected strategy: {strategy}"`.
   - Dispatch:
     - `"metadata"` -> `_run_metadata_first(query, effective_limit, model)`
     - `"semantic"` -> `_run_semantic_first(query, effective_limit)`
     - `"hybrid"` -> `_run_hybrid(query, effective_limit, model)`
   - Build and return `SearchResponse(results=results, strategy=effective_strategy, reasoning=reasoning, engine_gaps=engine_gaps)`.

**IMPORTANT implementation notes from CONTEXT.md (locked decisions):**
- Per-result engine attribution: FusedResult already has contributing_engines and engine_scores per dataclass definition (Plan 01)
- Per-engine individual scores AND fused RRF score: FusedResult.engine_scores holds originals, FusedResult.fused_score holds RRF score
- Auto mode reports strategy + reasoning: SearchResponse has both fields
- Default strategy is "auto": the `strategy` parameter defaults to "auto" in search() signature. BUT actually the config default_strategy should be used if the caller passes None explicitly. Keep it simple: default param = "auto" which matches cfg["default_strategy"] default.
- Same top-K fetch size from all engines: `fetch_size` computed once, passed to all three engines in _run_hybrid
- When one engine returns zero: engine_gaps tracks and exposes this in SearchResponse
