  <action>
    **1. Install pydantic-settings:**
    Add `pydantic-settings>=2.7.0` to `requirements.txt` (after `tenacity`). Run `pip install pydantic-settings>=2.7.0`.

    **2. Create `pageindex/exceptions.py`:**
    Define the exception hierarchy per CONTEXT.md locked decisions:
    ```python
    class PageIndexError(Exception):
        """Base exception for all PageIndex errors."""
    class ConfigError(PageIndexError):
        """Raised when configuration is invalid or missing."""
    class IngestionError(PageIndexError):
        """Raised when document ingestion fails."""
    class SearchError(PageIndexError):
        """Raised when a search operation fails."""
    ```
    Each class should have a brief docstring. No additional logic needed.

    **3. Create `pageindex/api.py` with PageIndexSettings:**

    Define nested sub-models (plain `pydantic.BaseModel`, NOT `BaseSettings`):
    - `LLMSettings`: `completion_model` (default "gemini/gemini-2.0-flash"), `embedding_model` (default "gemini/gemini-embedding-001"), `embedding_dimensions` (default 768), `temperature` (default 0)
    - `SupabaseSettings`: `url` (str, required -- no default), `key` (str, required -- no default)
    - `IngestionSettings`: `metadata_pages` (3), `chunk_max_tokens` (800), `chunk_overlap` (0.1), `max_workers` (1), `max_embedding_batch` (250)
    - `RetrievalSettings`: `default_top_k` (10), `default_strategy` ("auto"), `rrf_k` (60), `engine_weights` (dict with metadata/semantic/description all 1.0), `global_min_score` (0.01), `internal_fetch_multiplier` (2)

    Define `PageIndexSettings(BaseSettings)`:
    - `model_config = SettingsConfigDict(env_prefix="PAGEINDEX_", env_nested_delimiter="__", yaml_file=str(Path(__file__).parent / "config.yaml"), yaml_file_encoding="utf-8", extra="ignore")`
    - Fields: `supabase: SupabaseSettings`, `llm: LLMSettings = LLMSettings()`, `ingestion: IngestionSettings = IngestionSettings()`, `retrieval: RetrievalSettings = RetrievalSettings()`
    - Override `settings_customise_sources` to set priority: `init_settings` > `env_settings` > `YamlConfigSettingsSource(settings_cls)` (see RESEARCH.md Pattern 1)

    **IMPORTANT -- Pitfall 4 (env_nested_delimiter):** With `env_prefix="PAGEINDEX_"` and `env_nested_delimiter="__"`, nested env vars use double underscore (e.g. `PAGEINDEX_SUPABASE__URL`). Since Supabase URL/key are the most commonly set env vars, also accept flat `SUPABASE_URL` and `SUPABASE_KEY` without prefix by adding a `model_validator(mode='before')` classmethod that checks for `SUPABASE_URL`/`SUPABASE_KEY` in `os.environ` and populates the `supabase` nested dict if not already provided via init kwargs or PAGEINDEX_ env vars. This way users can use either `PAGEINDEX_SUPABASE__URL` or the standard `SUPABASE_URL` env var.

    **IMPORTANT -- YAML supabase section:** The current `config.yaml` has `supabase: url_env: "SUPABASE_URL"` (env var names, not actual values). The pydantic-settings `SupabaseSettings` expects actual URL/key values, NOT env var names. The YAML source will try to populate `supabase.url` from the YAML `supabase.url_env` and fail. Handle this by: (a) making the YAML `supabase` section NOT contain `url`/`key` fields (they come from env vars or kwargs), or (b) using a validator that ignores `url_env`/`key_env` fields. The simplest approach: in `SupabaseSettings`, use `model_config = ConfigDict(extra="ignore")` so `url_env` and `key_env` from YAML are silently ignored, and the actual `url`/`key` values come from env vars or constructor kwargs.
  </action>

    Add to `pageindex/api.py` (below the settings classes):

    **1. Public `SearchResponse` dataclass:**
    This is a NEW type distinct from `pageindex.retrieval.models.SearchResponse` (the internal type). Fields per CONTEXT.md:
    - `results: list` -- list of `FusedResult` or `RetrievalResult` subclasses (from internal SearchResponse)
    - `query: str` -- the original query string
    - `strategy_used: str` -- which strategy was actually executed ("metadata", "semantic", "hybrid")
    - `scores: dict` -- engine-level score summary (e.g., `{"engine_gaps": [...], "result_count": N}`)
    - `timing: float` -- elapsed seconds for the search call
    - `reasoning: str` -- for auto mode: LLM reasoning; for manual: "User-selected strategy: X"

    Use `@dataclass` from stdlib (project convention from Phase 3 decision 03-01). Import `field` from dataclasses for default_factory on list/dict fields.

    **2. `IngestionResult` dataclass:**
    Per CONTEXT.md locked fields plus Claude's discretion for additional fields:
    - `document_id: str` -- the doc_id from Supabase
    - `document_name: str` -- the filename/document name
    - `chunks_created: int` -- number of chunks stored
    - `status: str` -- "succeeded", "failed", "skipped"
    - `error: str | None = None` -- error message if status is "failed"

    **3. `DocumentInfo` dataclass (for `retrieve()` return type):**
    - `doc_id: str`
    - `name: str`
    - `metadata: dict` -- full document metadata row
    - `tree: dict | None = None` -- tree structure if available
    - `chunks: list[dict] | None = None` -- optionally loaded chunks

    Use stdlib `dataclasses` (NOT pydantic) per project convention.
