# Phase 3.1: Ingestion Integration Fixes - Research

**Researched:** 2026-02-23
**Domain:** Python ingestion pipeline bug-fixing (config namespace separation, embedding data flow)
**Confidence:** HIGH

## Summary

Phase 3.1 fixes two integration bugs discovered by the v1.0 milestone audit that break the "Ingest PDFs" and "Search Description" end-to-end flows. Both bugs are low-complexity fixes in well-understood code -- no new libraries, no architectural changes, no external dependencies.

**ISSUE-01** is a config key collision: `pipeline.py` builds a single `pipeline_config` dict containing both ingestion-specific keys (`metadata_pages`, `chunk_max_tokens`, `chunk_overlap`) and tree-indexer keys (`if_add_node_id`, `if_add_node_text`, `if_add_node_summary`). This entire dict is passed to `stage_tree_index`, which feeds it to `ConfigLoader().load(merged)`. `ConfigLoader._validate_keys()` compares against top-level `config.yaml` keys and raises `ValueError: Unknown config keys: {'metadata_pages', 'chunk_max_tokens', 'chunk_overlap'}`. Every `ingest()` call crashes before processing any document.

**ISSUE-02** is a data gap: `stage_store` writes `doc_description` (text) to the documents table but never computes or stores the `description_embedding` (vector). The `description_embedding` column was added by migration 003 (Phase 3), after the ingestion pipeline (Phase 2) was designed. `search_description()` queries `match_descriptions` RPC which filters `WHERE d.description_embedding IS NOT NULL`, so freshly ingested documents always return zero results.

Additionally, `stage_extract_metadata` and `stage_chunk` receive config values via function parameter defaults (`metadata_pages=3`, `max_tokens=800`, `overlap_ratio=0.1`) rather than from the config dict, meaning config.yaml overrides for these values are silently swallowed by `process_single_document`. This is noted as tech debt in the audit and should be addressed as part of the config separation fix.

**Primary recommendation:** Split `pipeline_config` into separate `tree_config` (passed to `stage_tree_index`) and ingestion params (threaded as explicit arguments to downstream stages). Embed the description text during `stage_embed` and store the embedding vector during `stage_store`.

### Pattern 1: Config Separation (ISSUE-01 Fix)

**What:** Split the single `pipeline_config` dict in `pipeline.py:210-218` into two concerns: tree-indexer config keys and ingestion-specific parameters. Tree-indexer keys are passed to `stage_tree_index`. Ingestion params are threaded as explicit arguments to `stage_extract_metadata`, `stage_chunk`.

**Where to change:**
1. `pipeline.py:210-218` -- Build two separate dicts: `tree_config` (only `if_add_node_id`, `if_add_node_text`, `if_add_node_summary`) and keep ingestion params as local variables.
2. `pipeline.py:_process_with_rollback` -- Pass ingestion params alongside config.
3. `stages.py:process_single_document` -- Accept `metadata_pages`, `chunk_max_tokens`, `chunk_overlap` as explicit parameters and thread them to stages 2 and 4 (fixing the swallowed-config tech debt simultaneously).

**Example approach:**
```python
# pipeline.py -- Build separate configs
tree_config = {
    "if_add_node_id": "yes",
    "if_add_node_text": "yes",
    "if_add_node_summary": "yes",
}

# Thread ingestion params to process_single_document
pipeline = process_single_document(
    pdf_path=str(path),
    llm_provider=provider,
    tree_config=tree_config,
    metadata_pages=effective_metadata_pages,
    chunk_max_tokens=effective_chunk_max_tokens,
    chunk_overlap=effective_chunk_overlap,
)
```

```python
# stages.py -- process_single_document accepts explicit params
def process_single_document(
    pdf_path: str,
    llm_provider: LLMProvider,
    tree_config: dict | None = None,
    metadata_pages: int = 3,
    chunk_max_tokens: int = 800,
    chunk_overlap: float = 0.1,
) -> DocumentPipeline:
    ...
    stage_tree_index(pipeline, tree_config or {})
    stage_extract_metadata(pipeline, llm_provider, metadata_pages=metadata_pages)
    ...
    stage_chunk(pipeline, llm_provider, max_tokens=chunk_max_tokens, overlap_ratio=chunk_overlap)
    ...
```

### Pattern 2: Description Embedding During Ingestion (ISSUE-02 Fix)

**What:** Compute the embedding vector for `pipeline.description` during (or after) `stage_embed`, and write it to `description_embedding` during `stage_store`.

**Where to change:**
1. `models.py:DocumentPipeline` -- Add `description_embedding: list[float] | None = None` field.
2. `stages.py:stage_embed` -- After chunk embedding, embed the description text (single item batch) if `pipeline.description` is not None. Store result in `pipeline.description_embedding`.
3. `stages.py:stage_store` -- Write `description_embedding` to the documents table.
4. `db/documents.py:_METADATA_COLUMNS` -- Add `"description_embedding"` to the allowlist so `update_document()` can write it.

**Example approach:**
```python
# stages.py -- in stage_embed, after chunk embedding loop
if pipeline.description:
    desc_embeddings = _embed_batch(llm_provider, [pipeline.description])
    pipeline.description_embedding = desc_embeddings[0]
```

```python
# stages.py -- in stage_store, add to update_fields
if pipeline.description_embedding:
    update_fields["description_embedding"] = pipeline.description_embedding
```

```python
# documents.py -- add to _METADATA_COLUMNS
_METADATA_COLUMNS = {
    ...,
    "description_embedding",
}
```

### Anti-Patterns to Avoid

- **Passing all config keys in a flat dict across concerns:** This caused ISSUE-01. Tree-indexer config and ingestion config have different validation rules and consumers. Separate them at the boundary.
- **Relying on function default parameters instead of config values:** The current `stage_extract_metadata(metadata_pages=3)` and `stage_chunk(max_tokens=800)` defaults mean config.yaml overrides are swallowed when `process_single_document` does not thread the values through. Always thread config values explicitly.
- **Updating document columns through raw client calls to bypass `_METADATA_COLUMNS`:** Instead, add `description_embedding` to the allowlist so the existing guard pattern is preserved.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Description embedding | Custom embedding logic | `LLMProvider.embed([description])` (already used in `stage_embed`) | Same model, same dimensions, same retry pattern |
| Config validation | Custom key filtering | Separate tree/ingestion dicts at the boundary (no validation change needed in ConfigLoader) | ConfigLoader._validate_keys() is correct -- the problem is what we pass to it |

**Key insight:** No new infrastructure is needed. Every building block (embedding API, DB write path, config loading) already exists and is tested. The bugs are wiring issues at module boundaries.

## Common Pitfalls

### Pitfall 1: Forgetting `_METADATA_COLUMNS` Allowlist

**What goes wrong:** Writing `description_embedding` via `update_document()` silently drops it because `_METADATA_COLUMNS` in `documents.py:14-28` does not include `description_embedding`.
**Why it happens:** The column was added by migration 003 (Phase 3) after `documents.py` was written (Phase 1). The allowlist was never updated.
**How to avoid:** Add `"description_embedding"` to `_METADATA_COLUMNS` in the same plan that writes the embedding.
**Warning signs:** `update_document()` returns successfully but `description_embedding` is still NULL in the database.

### Pitfall 2: Breaking `_process_with_rollback` Signature

**What goes wrong:** `_process_with_rollback` currently takes `(pdf_path, llm_provider, config)`. If `process_single_document` signature changes, `_process_with_rollback` must match.
**Why it happens:** The rollback wrapper directly delegates to `process_single_document`.
**How to avoid:** Update `_process_with_rollback` to accept and forward the new parameters. Also update the `executor.submit()` call site in `ingest()`.
**Warning signs:** `TypeError` on argument count.

### Pitfall 3: Embedding a None/Empty Description

**What goes wrong:** If `stage_generate_description` fails or returns empty string, attempting to embed it wastes an API call and may produce a garbage vector.
**Why it happens:** Description generation uses LLM which can fail.
**How to avoid:** Guard with `if pipeline.description:` before embedding (truthy check rejects both None and empty string).
**Warning signs:** `description_embedding` set but `doc_description` is empty -- search returns irrelevant results.

### Pitfall 4: Embedding Batch Size Boundary

**What goes wrong:** Embedding a single description text is fine (within the 250-batch limit), but if done inside the chunk embedding loop, the batch count could be off.
**Why it happens:** Mixing description embedding with chunk embedding batches.
**How to avoid:** Embed the description as a separate single-item call after the chunk embedding loop. Use the existing `_embed_batch` helper which has retry built in.
**Warning signs:** Off-by-one in embedding indices, wrong vector stored.

### Pitfall 5: ConfigLoader Validation Still Failing After Fix

**What goes wrong:** If the tree_config dict still contains any non-top-level keys, ConfigLoader._validate_keys() will still raise.
**Why it happens:** Incomplete separation -- some ingestion key leaks into tree_config.
**How to avoid:** Build tree_config as a whitelist of known tree-indexer keys (`if_add_node_id`, `if_add_node_text`, `if_add_node_summary`), not as a filter of the full dict. The audit explicitly lists which keys are valid top-level: `model`, `toc_check_page_num`, `max_page_num_each_node`, `max_token_num_each_node`, `if_add_node_id`, `if_add_node_summary`, `if_add_doc_description`, `if_add_node_text`.
**Warning signs:** `ValueError: Unknown config keys` still raised after fix.

## Code Examples

### ConfigLoader._validate_keys() -- The Root Cause of ISSUE-01

```python
# Source: pageindex/utils.py lines 776-779
def _validate_keys(self, user_dict):
    unknown_keys = set(user_dict) - set(self._default_dict)
    if unknown_keys:
        raise ValueError(f"Unknown config keys: {unknown_keys}")
```

`self._default_dict` contains only top-level config.yaml keys: `model`, `toc_check_page_num`, `max_page_num_each_node`, `max_token_num_each_node`, `if_add_node_id`, `if_add_node_summary`, `if_add_doc_description`, `if_add_node_text`, `llm`, `supabase`, `ingestion`. The ingestion-specific keys (`metadata_pages`, `chunk_max_tokens`, `chunk_overlap`) are nested under the `ingestion:` key, not at the top level.

## Open Questions

1. **Should `backfill_description_embeddings()` still exist after the fix?**
   - What we know: After this fix, new ingestions will populate `description_embedding`. But documents already ingested (before the fix) would still need backfill.
   - What's unclear: Are there existing ingested documents in the database without embeddings?
   - Recommendation: Keep `backfill_description_embeddings()` as-is. It is already idempotent (filters on `description_embedding IS NULL`). It serves as a safety net for pre-existing data and can be called once after deploying the fix.

2. **Should `if_add_doc_description` in config.yaml be set to "no" now?**
   - What we know: The tree-indexer's `page_index_main` can also generate descriptions (via `if_add_doc_description: "yes"` in config.yaml). The ingestion pipeline generates descriptions separately in `stage_generate_description`. Currently `if_add_doc_description` is `"no"`.
   - What's unclear: Whether anyone relies on the tree-indexer description path.
   - Recommendation: Leave `if_add_doc_description: "no"` (current default). The ingestion pipeline's description generation is the intended path.
