  <action>
    Fix ISSUE-02 (description_embedding never computed or stored during ingestion).

    **In `models.py`:**

    1. Add `description_embedding` field to the `DocumentPipeline` dataclass:
       ```python
       description_embedding: list[float] | None = None
       ```
       Place it after the `description` field (after line 72). Update the class docstring to document it.

    **In `stages.py`:**

    2. At the END of `stage_embed` (after the chunk embedding loop, around line 327 `pipeline.embeddings = all_embeddings`), add description embedding computation:
       ```python
       # Embed description text for description-based search
       if pipeline.description:
           desc_embeddings = _embed_batch(llm_provider, [pipeline.description])
           pipeline.description_embedding = desc_embeddings[0]
       ```
       This uses the existing `_embed_batch` helper which has tenacity retry built in. It is a separate single-item call AFTER the chunk embedding loop (Pitfall 4 from RESEARCH.md: do not mix with chunk batches). Guard with `if pipeline.description:` to reject both None and empty string (Pitfall 3).

    3. In `stage_store` (around line 354-355), add description_embedding write AFTER the existing `doc_description` write:
       ```python
       if pipeline.description_embedding:
           update_fields["description_embedding"] = pipeline.description_embedding
       ```

    **In `documents.py`:**

    4. Add `"description_embedding"` to the `_METADATA_COLUMNS` set (line 14-28). Without this, `update_document()` silently drops the field (Pitfall 1 from RESEARCH.md).

    **Why this works:** Once `description_embedding` is populated and stored during ingestion, the existing `match_descriptions` RPC (from migration 003) will find documents because its `WHERE d.description_embedding IS NOT NULL` filter will pass. The `search_description()` function and `backfill_description_embeddings()` utility are already correct and need no changes.
  </action>

    4. Grep for `description_embedding` in documents.py returns a match in _METADATA_COLUMNS
  </verify>
