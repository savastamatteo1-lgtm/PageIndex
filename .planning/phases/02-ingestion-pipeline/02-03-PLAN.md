  <action>
    Create `pipeline.py` with the main `ingest()` function and supporting helpers.

    **`ingest(directory: str, max_workers: int = 1, metadata_pages: int = 3, chunk_max_tokens: int = 800, chunk_overlap: float = 0.1) -> dict`:**

    This is a Python function (NOT CLI), following the `run_pageindex.py` pattern per user decision. The function:

    1. **Discover PDFs**: Use `sorted(Path(directory).glob("*.pdf"))` to find all PDFs in the directory. Log: `"Found {N} PDFs in {directory}"`

    2. **Filter already-ingested**: For each PDF, call `get_document_by_name(path.name)` from the DB layer. If a document exists with `ingestion_status == 'complete'`, skip it. Count skipped documents. Log: `"Processing {N}, skipping {M} already-ingested"`

    3. **Initialize LLM provider**: Call `get_provider()` from `pageindex.llm.provider` to get the singleton LLMProvider instance

    4. **Build config dict**: Assemble pipeline config from function parameters + config.yaml defaults. Include metadata_pages, chunk_max_tokens, chunk_overlap, and PageIndex config overrides (if_add_node_id='yes', if_add_node_text='yes', if_add_node_summary='yes')

    5. **Process with ThreadPoolExecutor**:
       ```python
       with ThreadPoolExecutor(max_workers=max_workers) as executor:
           futures = {
               executor.submit(_process_with_rollback, path, provider, config): path
               for path in to_process
           }
           for i, future in enumerate(as_completed(futures), 1):
               path = futures[future]
               try:
                   future.result()
                   results["succeeded"] += 1
                   logger.info(f"[{i}/{total}] SUCCESS: {Path(path).name}")
               except Exception as e:
                   results["failed"] += 1
                   results["errors"].append({"path": str(path), "error": str(e)})
                   logger.error(f"[{i}/{total}] FAILED: {Path(path).name} - {e}")
       ```

    6. **Log batch summary**: `"Batch complete: X succeeded, Y failed, Z skipped"`. Also log each failed document path and error type.

    7. **Write local batch log file** (per CONTEXT.md locked decision on dual tracking):
       - At batch end, write `{directory}/ingest_errors.jsonl` containing one JSON line per failed document: `{"path": str, "error": str, "timestamp": ISO8601}`
       - Only write the file if there are failures (`results["errors"]` is non-empty); skip file creation on clean runs
       - Use `Path(directory) / "ingest_errors.jsonl"` for the output path
       - Append mode (`"a"`) so consecutive runs accumulate in the same file
       - This satisfies the "local batch log file with paths and error messages" requirement alongside the DB `ingestion_status` column

    8. **Return results dict**: `{"succeeded": int, "failed": int, "skipped": int, "errors": [{"path": str, "error": str}]}`

    **`_process_with_rollback(pdf_path: str, llm_provider: LLMProvider, config: dict) -> DocumentPipeline`:**

    Wrapper around `process_single_document` that handles rollback:
    - Call `process_single_document(pdf_path, llm_provider, config)`
    - If any exception occurs:
      - Log the error
      - If a doc_id was created (check by looking up the document by name), delete it via `delete_document(doc_id)` to cascade-remove all related data
      - Re-raise the exception for the batch handler to log

    **Logging setup:**
    Use `logging.getLogger("pageindex.ingestion")` as the logger. Per user decision: structured logging via Python logging module, per-document status lines, no progress bars.

    **Important implementation notes:**
    - Do NOT use asyncio for the batch orchestrator. Use ThreadPoolExecutor per user decision. This avoids nested event loop issues since page_index_main() internally calls asyncio.run().
    - Each thread processes one document at a time through all 6 stages sequentially.
    - The shared Supabase client singleton should work across threads (httpx is thread-safe). If issues arise, this can be addressed with threading.local() later.
    - Default `max_workers=1` per user decision (sequential by default, configurable for parallelism).
