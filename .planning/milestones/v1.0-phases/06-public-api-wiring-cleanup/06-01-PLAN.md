Three changes in this task:

**1. Flat-kwargs support in `_populate_supabase_from_env` (ISSUE-05):**

In the `_populate_supabase_from_env` model_validator in `PageIndexSettings`, add handling for `supabase_url` and `supabase_key` top-level kwargs BEFORE the existing env var fallback logic. Use `values.pop("supabase_url", None)` and `values.pop("supabase_key", None)` to extract them (pop so pydantic doesn't reject unknown fields). Then restructure into `supabase: {"url": ..., "key": ...}` following the same pattern as the existing env var handling. The flat kwargs should take priority over env vars but not over an already-provided `supabase` dict.

Order of precedence within the validator:
1. If `supabase` dict already fully provided -> use it
2. If flat kwargs `supabase_url`/`supabase_key` provided -> restructure into `supabase` dict
3. If env vars `SUPABASE_URL`/`SUPABASE_KEY` exist -> use as fallback (existing logic)

**2. Retrieval config threading (ISSUE-06):**

In `strategy.py`, add an optional `retrieval_overrides: dict | None = None` parameter to the `search()` function. When provided, merge it into the `cfg` dict loaded by `load_retrieval_config()` using `cfg.update(retrieval_overrides)` so the overrides take precedence. Pass `cfg` to `_run_hybrid()` and `_run_metadata_first()` as a new `cfg` parameter so they use the merged config instead of re-reading from `load_retrieval_config()`.

In `_run_hybrid()`, add `cfg: dict | None = None` parameter. If `cfg` is None, fall back to `load_retrieval_config()`. Use this cfg for all config reads (`internal_fetch_multiplier`, `rrf_k`, `engine_weights`, `global_min_score`).

In `_run_metadata_first()`, add `cfg: dict | None = None` parameter. If `cfg` is None, fall back to `load_retrieval_config()`. Use this cfg for `metadata_fallback_threshold`.

In `api.py PageIndex.search()`, pass `retrieval_overrides=self._settings.retrieval.model_dump()` to `strategy_search()`. This threads all RetrievalSettings fields (rrf_k, engine_weights, global_min_score, internal_fetch_multiplier, default_top_k, default_strategy) from the PageIndex instance to the strategy module.

**3. Tree-indexing model override (ISSUE-07):**

In `api.py _build_ingestion_config()`, return `{"model": self._settings.llm.completion_model}` instead of `{}`. This makes `ConfigLoader.load()` use the user-specified model for tree indexing. The `model` key is a valid top-level `config.yaml` key, so `ConfigLoader._validate_keys()` will accept it. Do NOT include other keys like `llm` or `retrieval` -- only valid top-level config.yaml keys are safe (Pitfall 1 from RESEARCH.md).

**1. Add `search_description()` method to PageIndex (ISSUE-08):**

Add a `search_description()` method to the PageIndex class, positioned after `search_tree()` (around line 499). Follow the exact same pattern as the existing `search_semantic()` and `search_metadata()` methods:

```python
def search_description(
    self, query: str, *, limit: int | None = None
) -> list:
    """Direct description (embedding similarity) search.

    Parameters
    ----------
    query : str
        Natural-language search query.
    limit : int | None
        Max results.  Defaults to ``retrieval.default_top_k``.

    Returns
    -------
    list[DescriptionResult]
        Ranked results from the description engine.
    """
    from pageindex.exceptions import SearchError
    from pageindex.retrieval.description import search_description as _search_desc

    effective_limit = limit or self._settings.retrieval.default_top_k
    try:
        return _search_desc(query, limit=effective_limit)
    except Exception as exc:
        raise SearchError(f"Description search failed: {exc}") from exc
```

Use lazy import for `search_description` from `pageindex.retrieval.description` to follow the established pattern. Wrap errors in `SearchError` for uniform exception handling.
