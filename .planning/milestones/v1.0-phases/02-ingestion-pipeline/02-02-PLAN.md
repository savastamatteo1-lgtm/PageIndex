<task type="auto">
  <name>Task 1: Implement per-document pipeline stages</name>
  <files>
    pageindex/ingestion/stages.py
  </files>
  <action>
    Create `stages.py` with the following functions. Use `tenacity` for LLM retry logic (install via `pip install tenacity>=8.2.0` if not already installed, and add to requirements.txt).

    **Stage 1: Tree Indexing**
    `stage_tree_index(pipeline: DocumentPipeline, config) -> None`:
    - Call `page_index_main(pipeline.pdf_path, opt=config_opts)` where config_opts MUST set:
      - `if_add_node_id='yes'` (needed for chunk traceability)
      - `if_add_node_text='yes'` (needed for chunking -- leaf node text must be available)
      - `if_add_node_summary='yes'` (useful for description generation context)
    - Use `ConfigLoader().load({...})` from `pageindex.page_index` to create the opts object, merging ingestion-specific overrides with defaults from config.yaml
    - Store `result['structure']` in `pipeline.tree_json` and `result['doc_name']` in `pipeline.doc_name`
    - Important: `page_index_main()` internally calls `asyncio.run()`. This is fine inside ThreadPoolExecutor threads but would fail if the caller is already in an async context. Do NOT wrap in asyncio.

    **Stage 2: Metadata Extraction**
    `stage_extract_metadata(pipeline: DocumentPipeline, llm_provider: LLMProvider, metadata_pages: int = 3) -> None`:
    - Extract text from first N pages using `get_text_of_pages(pipeline.pdf_path, 1, metadata_pages, tag=False)`
    - Load vocabulary via `load_vocabulary()` from prompts module
    - Build system prompt via `build_metadata_extraction_prompt(vocabulary)`
    - Call `litellm.completion()` directly (not `provider.complete()`) because we need `response_format` parameter:
      ```python
      response = litellm.completion(
          model=llm_provider.completion_model,
          messages=[{"role": "system", "content": system_prompt}, {"role": "user", "content": text}],
          response_format={"type": "json_schema", "json_schema": METADATA_JSON_SCHEMA},
          temperature=0,
      )
      ```
    - Parse JSON from response: `json.loads(response.choices[0].message.content)`
    - Store in `pipeline.metadata`
    - If any of the required fields (doc_type, date, authority) are null, set `pipeline.needs_review = True`
    - Wrap the LLM call with `@retry(wait=wait_random_exponential(min=1, max=30), stop=stop_after_attempt(3))` from tenacity. Define a helper function `_call_llm_with_retry()` or use the decorator on an inner function.

    **Stage 3: Description Generation**
    `stage_generate_description(pipeline: DocumentPipeline, llm_provider: LLMProvider) -> None`:
    - Build a clean version of the tree structure for the prompt (remove `text` fields to save tokens, keep titles and summaries)
    - Use `llm_provider.complete()` with the description system prompt and tree structure as user message
    - Store result in `pipeline.description`
    - Wrap with tenacity retry (same pattern as stage 2)

    **Stage 4: Chunking**
    `stage_chunk(pipeline: DocumentPipeline, llm_provider: LLMProvider, max_tokens: int = 800, overlap_ratio: float = 0.1) -> None`:
    - Get leaf nodes via `get_leaf_nodes(pipeline.tree_json)`
    - Call `chunk_leaf_nodes()` from chunker module, passing `count_tokens_fn=llm_provider.count_tokens`
    - Store result in `pipeline.chunks`

    **Stage 5: Embedding**
    `stage_embed(pipeline: DocumentPipeline, llm_provider: LLMProvider) -> None`:
    - Build embedding text for each chunk using `build_embedding_text(chunk, combined_metadata)` where combined_metadata includes pipeline.metadata + doc_name + description
    - Validate each embedding text does not exceed the embedding model's token limit (2048 tokens for Gemini). If it does, truncate the chunk content (NOT the metadata prefix) and rebuild
    - Call `llm_provider.embed(texts)` with all embedding texts. If there are more than 250 texts, batch into groups of 250 (Gemini API limit per call)
    - Store embeddings in `pipeline.embeddings`
    - Wrap embed call with tenacity retry

    **Stage 6: Storage**
    `stage_store(pipeline: DocumentPipeline) -> None`:
    - Update the document row (already inserted earlier with status=processing) with extracted metadata, description, and needs_review flag using `update_document()`
    - Store tree via `insert_tree(pipeline.doc_id, pipeline.tree_json)` -- but strip `text` fields from tree_json before storage to save DB space (the text is already in chunks). Create a helper `_strip_text_from_tree(tree_json)` that deep-copies and removes `text` keys from all nodes
    - Store chunks via `insert_chunks()` with embedding vectors. Build the chunk dicts from pipeline.chunks and pipeline.embeddings, including doc_id, content, embedding, node_id, metadata
    - Mark document as complete: `update_document(pipeline.doc_id, {"ingestion_status": "complete"})`

    **Orchestrator function:**
    `process_single_document(pdf_path: str, llm_provider: LLMProvider, config: dict) -> DocumentPipeline`:
    - Create DocumentPipeline from pdf_path
    - Insert document record with status=processing: `insert_document(doc_name, {"ingestion_status": "processing"})`
    - Store the returned doc_id in pipeline.doc_id
    - Run stages 1-6 in sequence
    - Return the completed pipeline
    - Do NOT catch exceptions here -- the batch orchestrator (Plan 03) handles rollback

    All stages mutate the `DocumentPipeline` object in-place (no return values needed -- the pipeline accumulates state).

    Also add `tenacity` to `requirements.txt` if not already present.
