Output: `pageindex/retrieval/semantic.py` (semantic search with DocScore) and `pageindex/retrieval/description.py` (description similarity search with backfill).

  <action>
Create `pageindex/retrieval/semantic.py` with the semantic search pipeline:

1. **embed_query(query: str) -> list[float]** function:
   - Uses `get_provider().embed([query])` to get a single query embedding
   - Returns the embedding vector (first element of the returned list)
   - This is a separate function so the embedding can be reused by the description engine (per RESEARCH.md anti-pattern note: a single query embedding CAN be shared since both use the same embedding model and 768 dimensions)

2. **compute_doc_scores(chunk_results: list[dict]) -> list[dict]** function:
   - Per REQUIREMENTS.md canonical formula: `DocScore = (1/sqrt(N+1)) * sum(ChunkScore(n))`
   - Groups chunks by `doc_id` using `collections.defaultdict(list)`
   - For each doc_id, computes:
     - `n = len(similarities)` (number of matching chunks)
     - `raw_sum = sum(similarities)`
     - `doc_score = (1 / math.sqrt(n + 1)) * raw_sum`
   - Returns list of dicts: `{"doc_id": str, "score": float, "chunk_count": int}`
   - Sorted by score descending
   - This resolves the DocScore formula inconsistency flagged in STATE.md (REQUIREMENTS.md formula is canonical per RESEARCH.md Open Question 2)

3. **search_semantic(query: str, limit: int | None = None, query_embedding: list[float] | None = None, match_threshold: float | None = None) -> list[SemanticResult]** function:
   - Main entry point for semantic search
   - If `query_embedding` is None, compute it via `embed_query(query)` -- allows caller to pass pre-computed embedding for sharing
   - Resolve limit from parameter -> config -> DEFAULT_TOP_K
   - Resolve match_threshold from parameter -> config -> 0.7 (match_chunks default)
   - Call `match_chunks(query_embedding, match_threshold=match_threshold, match_count=limit * 5)` -- request more chunks than top-K since multiple chunks map to same document (5x is a reasonable multiplier)
   - If no chunks returned: return empty list
   - Call `compute_doc_scores()` on chunk results
   - Filter out documents below `DOCSCORE_MIN_THRESHOLD` from config
   - Take top `limit` documents
   - For each scored document, fetch full document metadata via `get_document(doc_id)`
   - Convert to `SemanticResult` objects with `engine_name="semantic"`, `confidence` from `assign_confidence()`, `chunk_count` from computation
   - Return list of SemanticResult

Import `math`, `collections.defaultdict`. Import `match_chunks` from `pageindex.db.chunks`, `get_document` from `pageindex.db.documents`, `get_provider` from `pageindex.llm.provider`, models and config from `pageindex.retrieval`.

Create `pageindex/retrieval/description.py` with the description search pipeline:

1. **search_description(query: str, limit: int | None = None, query_embedding: list[float] | None = None) -> list[DescriptionResult]** function:
   - Main entry point for description-based search
   - Per locked decision: uses embedding similarity (not LLM per-query), fast, reuses infrastructure
   - If `query_embedding` is None, compute via `embed_query(query)` from `pageindex.retrieval.semantic` (reuse per RESEARCH.md recommendation)
   - Resolve limit from parameter -> config -> DEFAULT_TOP_K
   - Call `get_client().rpc("match_descriptions", {"query_embedding": query_embedding, "match_threshold": DESCRIPTION_MIN_THRESHOLD, "match_count": limit}).execute()`
   - If no results: return empty list
   - For each result, fetch full document metadata via `get_document(doc_id)` (match_descriptions returns doc_id, doc_name, doc_description, similarity)
   - Convert to `DescriptionResult` objects with:
     - `engine_name="description"`
     - `score=result["similarity"]`
     - `confidence` from `assign_confidence()`
     - `doc_description=result["doc_description"]`
     - `metadata` from the full document row
   - Return list of DescriptionResult

2. **backfill_description_embeddings(batch_size: int = 250) -> dict** function:
   - Per RESEARCH.md Open Question 4: batch-embed all existing doc_description values where description_embedding is NULL
   - Query: `get_client().table("documents").select("doc_id, doc_description").is_("description_embedding", "null").not_.is_("doc_description", "null").execute()`
   - If no documents need backfill, return `{"backfilled": 0, "skipped": 0}`
   - Get provider via `get_provider()`
   - Process in batches of `batch_size` (per ingestion convention: 250 for Gemini API limits)
   - For each batch:
     - Extract description texts
     - Call `provider.embed(texts)` to get embeddings
     - For each (doc_id, embedding) pair, update the document: `get_client().table("documents").update({"description_embedding": embedding}).eq("doc_id", doc_id).execute()`
   - Log progress: "Backfilled {n}/{total} description embeddings"
   - Return `{"backfilled": count, "errors": error_count}` summary
   - Wrap individual updates in try/except to continue on errors (same resilience pattern as ingestion)
