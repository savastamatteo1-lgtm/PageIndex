  <action>
Create `pageindex/retrieval/tree_search.py` wrapping the existing PageIndex tree search for multi-document concurrent use:

1. **_get_tree_nodes(tree_json: dict) -> list[dict]** helper function:
   - Extract all nodes from the tree structure recursively (DFS)
   - Each node has: `title`, `node_id`, `start_index` (start page), `end_index` (end page), optionally `summary`
   - Returns flat list of all nodes

2. **_rebuild_node_text(doc_id: str, node_id: str, chunks: list[dict] | None = None) -> str** helper function:
   - Per Pitfall 6 from RESEARCH.md: tree JSON has text fields stripped by `_strip_text_from_tree` in stages.py
   - If `chunks` is None, load via `get_chunks_by_doc(doc_id)`
   - Find chunks whose metadata contains `node_id` matching the target
   - Concatenate their content text in order
   - Return reconstructed text (may be empty if no matching chunks found)

3. **_search_single_tree(doc_id: str, query: str, model: str) -> list[dict]** async function:
   - Load tree via `get_tree(doc_id)` -- returns None if no tree exists, return empty list
   - Extract tree_json from the row
   - Get all nodes via `_get_tree_nodes(tree_json)`
   - Load chunks once via `get_chunks_by_doc(doc_id)` for text reconstruction
   - Use the existing tree search approach: for each top-level node, check relevance via LLM
   - Build a system prompt that provides the query and asks the LLM which sections are most relevant based on section titles, summaries (if available), and reconstructed text snippets
   - Use `get_provider().acomplete()` for async LLM calls
   - Parse LLM response to identify relevant node_ids
   - For each relevant node, extract: `{"title": node["title"], "start_page": node["start_index"], "end_page": node["end_index"], "node_id": node["node_id"]}`
   - Return list of section dicts

4. **tree_search(doc_ids: list[str], query: str, model: str | None = None) -> list[TreeSearchResult]** async function:
   - Main entry point per locked decision: runs on top N documents (TREE_SEARCH_TOP_N from config, default 5)
   - Truncate doc_ids to TREE_SEARCH_TOP_N
   - Resolve model from parameter -> config -> default completion model
   - Use `asyncio.Semaphore(TREE_SEARCH_MAX_CONCURRENCY)` to limit concurrent LLM calls
   - Create tasks: `[_search_with_semaphore(sem, doc_id, query, model) for doc_id in doc_ids]`
   - Execute via `asyncio.gather(*tasks, return_exceptions=True)`
   - Filter out exceptions and None results (log exceptions as warnings)
   - For each successful result, fetch full document metadata via `get_document(doc_id)`
   - Convert to `TreeSearchResult` with:
     - `engine_name="tree_search"`
     - `score=len(sections) / total_nodes` (relevance as fraction of sections matched)
     - `confidence` from `assign_confidence()`
     - `sections` list with title, start_page, end_page, node_id
   - Return list of TreeSearchResult sorted by score descending

5. **tree_search_sync(doc_ids: list[str], query: str, model: str | None = None) -> list[TreeSearchResult]** convenience wrapper:
   - Wraps `tree_search()` with `asyncio.run()` for callers not already in an async context
   - Handles the case where an event loop is already running (use `loop.run_until_complete()` or create a new thread)

Import `asyncio`, `logging`. Import `get_tree` from `pageindex.db.trees`, `get_chunks_by_doc` from `pageindex.db.chunks`, `get_document` from `pageindex.db.documents`, `get_provider` from `pageindex.llm.provider`, models and config from `pageindex.retrieval`.
